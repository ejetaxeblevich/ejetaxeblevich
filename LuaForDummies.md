## Переменные

Это то, ***во что записывается информация*** - без переменных практически никак. Вспомните школьные уроки алгебры (но не воротите нос😂): там впервые для нас показали, что можно производить математические операции с БУКВАМИ. Вот эта буква - на самом деле число (а = 1) или... *да что угодно может под ней скрываться.*

> Если полученную информацию не записать "в именованную ячейку памяти", то игра это просто-напросто мгновенно забудет. Из этого следует то, что под каждую переменную ВЫДЕЛЯЕТСЯ ПАМЯТЬ, какая есть у игры в запасе - это не бесплатно. А если память кончится, то что? Пральна - вылет *(но это еще нужно постараться написать мощный яндередев)*.

Любая переменная имеет свое уникальное название. Оно может быть любыми латинскими буквами(с цифрами и с подчеркиванием) почти какой угодно длины, начиная с одного символа.

***

### Локальная переменная

Локальная переменная повсеместно используется в скриптах, функциях и триггерах.

- Быстрая. Lua лучше работает с локальными переменными.
- Существует только в ветке выполняемого скрипта, где была объявлена и не выходит за его пределы (поэтому и быстрая).
- Исчезает сразу после выполнения скрипта.
- Поддерживает конструкции с точкой `.` и двоеточием `:`.

#### Синтаксис:

Объявить переменную:
```lua
local a
```
Получить переменную:
```lua
a
```
Присвоить значение:
```lua
a = 1
```

#### Примеры использования:

Базовый вывод информации в консоль/лог игры:
```lua
local a = "test"

println(a)
LOG(a)
```
Получить объект с именем `MyCar` и удалить его:
```lua
local a = GetEntityByName("MyCar")
if a then 
    a:Remove() 
end
```
Создать переменную и тут же проверить ее значение:
```lua
local a = 1
if a == 1 then
    println("jopa")
else
    println("pisya")
end
```

#### Зона видимости:

Локальная переменная **не может быть получена** в скрипте, ветка которого находится выше той ветки, где была объявлена (окажется вне зоны видимости):
```lua
--Ветка А.
    if true then
        --Начало ветки Б.
        local a = 1    --> Создали локально `a` внутри ветки Б.
    end
if a == 1 then
--ОШИБКА. `a` вне видимости веткой А. Переменная равна `nil`.
```

### Глобальная переменная

Глобальная переменная заметно реже используется, чем локальная в скриптах, функциях и триггерах.

- Медленнее, чем локальная. Lua хуже работает с глобальными переменными.
- Существует внутри всего процесса, где была объявлена. Проще говоря по всей игре (поэтому и медленнее).
- Исчезает после закрытия игры.
- Поддерживает конструкции с точкой `.` и двоеточием `:`.

#### Синтаксис:

> Имя переменной не обязательно должно начинаться с `GL_`, просто это удобное обозначение, что переменная *глобальная* (типа GLOBAL, you know).

Объявить переменную:
```lua
GL_a = <значение>
```
Получить переменную:
```lua
GL_a
```
Присвоить значение:
```lua
GL_a = 1
```

#### Примеры использования:

Базовый вывод информации в консоль/лог игры:
```lua
GL_test = "test"

println(GL_test)
LOG(GL_test)
```
Объявить глобальную переменную в одном триггере, а получить в другом:
```lua
--Триггер первый
GL_info = "jopa"

--Триггер второй
LOG(GL_info)
```
Объявить глобальную переменную на первой карте, переместится и получить на второй:
```lua
--`data\maps\r1m1\triggers.xml`
GL_prikol = true

--`data\maps\r1m2\triggers.xml`
if GL_prikol == true then
    exit()
end
```

#### Зона видимости:

- Если глобальная переменная объявлена в корне файла.lua, то будет важен порядок загрузки файлов в память игры.
- Если сначала прочитается получение, а потом ее создание, то будет ошибка.

### Переменная карты

Переменная карты очень часто используется в скриптах и триггерах.

- Игровая сущность. Для Lua без разницы (в отличие от игры).
- Существует только внутри той карты, где была объявлена. Полностью зависит от триггера `GlobalVar`.
- Остается в игре после сохранения и перезагрузки.
- Не может хранить несколько значений и логические значения.

#### Синтаксис:

Объявить переменную:
```lua
SetVar("a", <значение>)
```
Получить переменную:
```lua
GetVar("a")<интерпретация>
```
Что за интерпретации? Грубо говоря, это настройка функции на получение значения переменной (в какой вид его интерпретировать):

| Интерпретация | Попробует превратить в... |
|-----------|-----------|
|`.AsInt`|Цельное число|
|`.AsFloat`|Число с запятой|
|`.AsString`|Строку|
|`.AsTable`|Таблицу|
|`.AsNumList`|Несколько чисел|
|`.AsVector`|Игровой CVector|

Присвоить значение:
```lua
SetVar("a", 1)
```

#### Примеры использования:

Базовый вывод информации в консоль/лог игры:
```lua
SetVar("a", "popa")

local a = GetVar("a").AsString

println(a)
LOG(a)
```
Объявить переменную карты в одном триггере, а получить в другом:
```lua
--Триггер первый
local chance = random(2)
if chance == 1 then
    SetVar("a", "popa")
else
    SetVar("a", "pisya")
end

--Триггер второй
local a = GetVar("a").AsString
if a == "popa" then
    die()
end
```

#### Зона видимости:

- Только на одной игровой карте *(можно передать в другие переменные)*.
- Если сначала прочитается получение, а потом ее создание, то будет значение-заглушка `-1`.

### Окружение Lua

Самая сложная переменная - единое пространство имен Lua. *Это таблица, в которой содержатся все созданные глобальные переменные, функции Lua, другие таблицы и т.п*

- Медленнее, чем локальная. Lua хуже работает с глобальными переменными.
- Существует внутри всего процесса. Проще говоря по всей игре (поэтому и медленнее).
- Динамически изменяемая. Можно на ходу добавлять новые поля и редактировать старые (динамически *создавать* имена новых переменных).
- Поддерживает конструкции с точкой `.`.

#### Синтаксис:

Получить глобальное окружение:
```lua
_G
```
Получить значение поля из глобального окружения:
```lua
_G.GL_a
```
```lua
_G["GL_a"]
```
Присвоить значение полю в глобальном окружении:
```lua
_G.GL_a = 1
```
```lua
_G["GL_a"] = 1
```

#### Примеры использования:

Базовый вывод информации в лог игры:
```lua
for n in pairs(_G) do
    LOG(n)
end
```
Сгенерировать несколько глобальных переменных:
```lua
for i = 1, 5 do
    _G["NewVarName"..i] = i
end
```

#### Зона видимости:

- Внутри всего процесса игры.

## Типы данных

Это то, ***что определяет вид информации*** - очень важно различать переменные по их типам данных. Вспомните школьные уроки информатики (но не воротите нос😂): там впервые для нас показали, что для компьютера есть такие понятия как: *Целое число*, *Число с плавающей запятой*, *Строка*, *Логическое значение*...

> **С определенным типом данных можно сделать только то, что он может позволить с собой сделать.** Если это правило нарушается - возникает ошибка, ломающая целые скрипты! Каждый тип данных имеет свой размер занимаемое памяти вне зависимости от его переменной, но говорить в этой статье про это будет слишком профессионально...

Любой тип данных имеет выделенные символы, какими он обозначается.

***

### Числовой

Числовой тип данных (число / `number` ) - это целое число или число с запятой. Числа можно использовать во всех математических операциях: хранить информацию, заниматься арифметикой с помощью специальных Lua-функций, производить отладку в логе игры...

- Возвращает ИСТИНУ всегда, если существует.

> Число может иметь математические символы.

#### Синтаксис:

Целое число:
```lua
1
```
Число с ТОЧКОЙ (запятой):
```lua
1.0
```
```lua
-1.0000
```

#### Примеры использования:

Базовый вывод информации в консоль/лог игры:
```lua
local a = 1

println(a)
LOG(a)
```
Что-то посчитаем:
```lua
local a = 67
local b = 12.345

local c = (a + b) / 2^11

println(c)
LOG(c)
```

### Строчный

Строчный тип данных (строка / `string` ) - это контейнер с какими-то символами или текстом. Строки можно использовать везде: хранить информацию, читать ее специальными Lua-функциями, производить отладку в логе игры...

- Возвращает ИСТИНУ всегда, если существует.

> Строка может иметь управляющие спецсимволы (паттерны) для Lua-функций и бинарные символы.

#### Синтаксис:

Пустая строка:
```lua
""
```
Вариант-инверсия во избежание конфликтов двойных кавычек (пустая):
```lua
''
```
Вариант для игнорирования управляющих последовательностей (пустая):
```lua
[[]]
```

Заполненная строка:
```lua
"text"
```
```lua
"a_ko3@6s54$ns&ni7=3u"
```

Код склеивания строк *(конкатенация)*:
```lua
..
```

Базовый вывод информации в консоль/лог игры:
```lua
local MyText = "text"

println(MyText)
LOG(MyText)
```
Динамическое формирование строки *(конкатенация)*:
```lua
local Hello = "Hello"
local World = "World!"

local MyText = Hello .. " " .. World

println(MyText)
LOG(MyText)
--Вывод: `"Hello World!"`
```

```lua
local text = "Hello, World!"

local MyText = string.gsub(text, ",", "")
--Убрали запятую: заменили "," на "" в text.

println(MyText)
LOG(MyText)
--Вывод: `"Hello World!"`
```

### Логический 

Логический тип данных (булевый / bool / `boolean`) - это утверждение о каком-либо объекте, которое может быть либо истинным, либо ложным.

В Lua еще есть третье утверждение - пустое, и оно ближе по духу к лжи. 

- Возвращает ИСТИНУ, ЛОЖЬ или ПУСТОТУ в любом случае.

> Любая сущность в скрипте, что **НЕ ЯВЛЯЕТСЯ** ЛОЖЬЮ или ПУСТОТОЙ будет ИСТИНОЙ.

#### Синтаксис:

ИСТИНА (да):
```lua
true
```
ЛОЖЬ (нет):
```lua
false
```
ПУСТОТА (хз😂):
```lua
nil
```

#### Примеры использования:

Базовый вывод информации в консоль/лог игры:
```lua
println(a)    --> `a` не существует и она является ПУСТОТОЙ `nil`
LOG(a)
--Вывод: `nil`

local a
println(a)    --> `a` существует, но ее значение ПУСТОТА `nil`
LOG(a)
--Вывод: `nil`

a = true
println(a)    --> `a` существует и ее значение ИСТИНА `true`
LOG(a)
--Вывод: `true`

a = false
println(a)    --> `a` существует и ее значение ЛОЖЬ `false`
LOG(a)
--Вывод: `false`

a = 1
println(a)    --> `a` существует и ее значение число `1`, что в Lua является ИСТИНОЙ `true` (как `0` и `-1`)
LOG(a)
--Вывод: `1`

a = "text"
println(a)    --> `a` существует и ее значение строка `text`, что в Lua является ИСТИНОЙ `true` (как и пустая строка `""`)
LOG(a)
--Вывод: `text`

a = {}
println(a)    --> `a` существует и ее значение таблица, что в Lua является ИСТИНОЙ `true` (как и заполненная таблица)
LOG(a)
--Вывод: `table: 23638DF8`

a = CVector(1,2,3)
println(a)    --> `a` существует и ее значение игровой объект (вектор координат), что в Lua является ИСТИНОЙ `true` (как и любой СУЩЕСТВУЮЩИЙ игровой объект)
LOG(a)
--Вывод: `(1.000, 2.000, 3.000)`
```

### Таблица

Тип данных таблицы (список / словарь / `table`) - это контейнер, который может содержать множество различных элементов и иметь иерархию (как папки на компьютере). Таблицы очень удобно использовать для хранения комплексной информации или составления продвинутых объектов с методами.

- Возвращает ИСТИНУ всегда, если существует.

> Любое значение из таблицы, как и сама переменная таблицы является **ССЫЛКОЙ** на таблицу, а не буквальное значение "здесь и сейчас", как у других типов данных. Редактируя переменную таблицы - происходит редактирование оригинала, где бы он не находился!

Любая заполненная таблица имеет некоторую последовательность индексов(для списка) или ключей(для словаря) со значениями.

#### Синтаксис:

Пустая таблица:
```lua
{}
```
Заполненная таблица (список):
```lua
{1,2,3}
```
```lua
{"hornet01","specter01","pkt01","kord01","storm01","rapier01","vector01","vulcan01","flag01","kpvt01","rainmetal01","bumblebee01","omega01"}
```

## Логические операции

Это то, ***что позволяет выполнять выбор*** - без логических операций вообще никак. Еще раз вспомните школьные уроки информатики (но не воротите нос😂): там впервые для нас показали, что для компьютера есть такие понятия как: *Истина*, *Ложь*, *И*, *Или*...

> Скрипт всегда выполняется сверху вниз, строчка за строчкой - и его ход можно менять. Но под каждую логическую операцию ВЫДЕЛЯЕТСЯ ПАМЯТЬ, какая есть у игры в запасе - это не бесплатно. А если память кончится, то что? Пральна - вылет *(но это еще нужно постараться написать мощный яндередев)*.

Любая логическая операция имеет выделенные символы и специальные слова, каким бы сложной она не была. *Эти символы и слова уникальны и не могут быть использованы как имена чего-то другого в скрипте.*

***

### Сравнение

Сравнить можно практически что угодно с чем угодно. ***Основано на типах данных.***

- Существует только в моменте выполнения себя, где было объявлено.
- Выполняется как математическое уравнение (или как геймплей игры "2048").
- Поддерживает конструкции с круглыми скобками `(`, `)` и логическими операторами `and`, `or`, `not` и другими.

#### Приоритет:

У логических операторов есть приоритет выполнения, как в уравнениях.

| Оператор | Приоритет |
|-----------|-----------|
| `()` | Наивысший |
| `not` | Высокий |
| `==`, `~=`, `<`, `<=`, `>`, `>=` | Средний |
| `and` | Низкий |
| `or` | Самый низкий |

Еще есть другие операторы, но все они выполняются перед тем, как произвести сравнение значений операторами выше (кроме скобок - они самые главные).

#### Синтаксис:

Построение сравнений с логическими операторами. Возвращают результат вычислений.

| Конструкция | Сравнение | Формулировка |
|-----------|-----------|-----------|
|`a > b`|***Больше, чем*** <br> *(только числа)*|Является ли `a` больше, чем `b`?|
|`a < b`|*\***Меньше, чем*** <br> *(только числа)*|Является ли `a` меньше, чем `b`?|
|`a == b`|***Равно*** <br> *(любые типы)*|Являются ли `a` с `b` одним и тем же?|
|`a ~= b`|***Не равно*** <br> *(любые типы)*|Являются ли `a` с `b` разными?|
|`a >= b`|***Больше или равно, чем*** <br> *(только числа)*|Является ли `a` больше, чем `b` или равно?|
|`a <= b`|***\*Меньше или равно, чем*** <br> *(только числа)*|Является ли `a` меньше, чем `b` или равно?|
|`a and b`|***И*** <br> *(любые типы)*|Является ли `a` истиной? Тогда результат `b`. Иначе результат `a`.|
|`a or b`|***ИЛИ*** <br> *(любые типы)*|Является ли `a` истиной? Тогда результат `a`. Иначе результат `b`.|
|`not a`|***НЕ*** <br> *(любой тип)*|Является ли `a` истиной? Тогда ложь. Иначе истина.|
| | | |
|`a and b == c or d`|*Комбинация* из нескольких <br> *(любые типы)*|Являются ли `b` с `c` одним и тем же? Тогда их результат истина, иначе ложь (шаг 1). Является ли `a` истиной? Тогда результат из *шага 1*, иначе результат `a` (шаг 2). Является ли результат из *шага 2* истиной? Тогда результат *шага 2*, иначе результат `d` (шаг 3) = общий результат.|
|`a or b == (c and d)`|*Комбинация* из нескольких <br> *(любые типы)*|Является ли `c` истиной? Тогда результат `d`, иначе результат `c` (шаг 1). Являются ли `b` с результатом из *шага 1* одним и тем же? Тогда истина, иначе ложь (шаг 2). Является ли `a` истиной? Тогда результат из *шага 2*, иначе результат `a` (шаг 3) = общий результат.|

*\*Lua вызывает ошибку, если это не условие цикла (лексер вероятно думает, что это открытие xml тега).*

#### Примеры использования:

Базовый вывод информации в консоль/лог игры:
```lua
local a = true
local result = a == false

println(result)
LOG(result)
--Вывод: `false`
```
```lua
local a = 1
local b = 2
local result = a > b
```
```lua
local a
local b = "text"
local result = a or b
```

### Проверка условия

Условие на изменение хода выполнения скрипта по другой ветке - для этого результат условия должен быть истиной. ***Основано на сравнении.***

- Условие выполняется, если его результат ИСТИНА.
- Существует только в моменте выполнения себя, где было объявлено.
- Создает новые ветки скриптов ЕСЛИ (без циклов/итераторов).
- Может быть использовано для работы циклов/итераторов.

#### Синтаксис:

Простая проверка условия:
```lua
if a then

end
```
| Кусочек кода | Определение |
|-----------|-----------|
| `if` | Начало проверки условия |
| `a` | Условие |
| `then` | Конец проверки уловия |
| от `then`<br>до `end` | Тело `if`.<br>Является ли условие `a` истиной? Тогда код внутри тела выполнится. Иначе пропуск.|
| `end` | Конец тела `if`. |


Проверка условия с вариантом если оно не выполняется:
```lua
if a then

else

end
```
| Кусочек кода | Определение |
|-----------|-----------|
| от `then`<br>до `end` | Тело `if`|
| от `then`<br>до `else` | Первая ветка `if`.<br>Является ли условие `a` истиной? Тогда этот код внутри тела выполнится. Иначе пропуск.|
| от `else`<br>до `end` | Вторая ветка `if`.<br>Этот код внутри тела выполнится, если никакое условие `if` не было истиным. Иначе пропуск.|


Проверка нескольких условий (если одно не выполняется, переходит к следующему и т.д):
```lua
if a then

elseif b then

end
```
| Кусочек кода | Определение |
|-----------|-----------|
| от `then`<br>до `elseif` | Первая ветка `if`.<br>Является ли условие `a` истиной? Тогда этот код внутри тела выполнится. Иначе пропуск.|
| от `elseif`<br>до `then` | Второе условие `b`, если первое условие `a` ложь или пустое.|
| от `then`<br>до `end` | Вторая ветка `if`.<br>Является ли условие `b` истиной? Тогда этот код внутри тела выполнится. Иначе пропуск.|


Комбинированная проверка нескольких условий (если ни одно не выполняется, выполнит последнее):
```lua
if a then

elseif b then

else

end
```

Можно проверки складывать друг в друга, образуя ветки логики:
```lua
if a then
    if b then

    end
else

end
```

#### Примеры использования:

Базовый вывод информации в консоль/лог игры:
```lua
local a = true
if a then
    println("popa")
    LOG("popa")
else
    println("pisya")
    LOG("pisya")
end
```
```lua
local a = 2
if a == 1 then
    println("pisya")
    LOG("pisya")
elseif a >= 2 then
    println("popa")
    LOG("popa")
end
```

## Циклические операции

Это то, ***что позволяет выполнять однотипный код множество раз*** - очень нужная вещь для экономии строк кода. ***Основано на логических операциях.***

> Скрипт всегда выполняется сверху вниз, строчка за строчкой - и его можно повторять сколько нужно. Но под каждую циклическую операцию (итерацию) ВЫДЕЛЯЕТСЯ ПАМЯТЬ, какая есть у игры в запасе - это не бесплатно. А если память кончится, то что? Пральна - вылет ***(а тут даже без яндередева можно кринжануть)***.

Циклические операции = циклы / итераторы.

Любая циклическая операция имеет выделенные символы и специальные слова, каким бы сложной она не была. *Эти символы и слова уникальны и не могут быть использованы как имена чего-то другого в скрипте.*

***

### Цикл while

Может стать обычным счетчиком с проверкой условия.

- Начнет выполнять код, если его условие выполняется.
- Выполняет код до тех пор, пока его условие выполняется.
- Существует только в моменте выполнения себя, где было объявлено.

> ***Если его условие всегда будет истиной, он не завершится и игра зависнет!***

#### Синтаксис:

Простая проверка условия:
```lua
while a do

end
```
| Кусочек кода | Определение |
|-----------|-----------|
| `while` | Начало проверки условия цикла |
| `a` | Условие |
| `do` | Конец проверки условия цикла |
| от `do`<br>до `end` | Тело `while`.<br>Является ли условие `a` истиной? Тогда код внутри тела будет выполняться, пока условие `a` остается истиной. Иначе выход из цикла.|
| `end` | Конец тела `while`. |

> Код внутри цикла выполняется полностью, даже если условие изменилось на середине.

Работа цикла:
1. Проверка условия;
2. Если истина - выполнение кода внутри тела;
3. Проверка условия;
4. Если истина - выполнение кода внутри тела...

Выйти из цикла - `break`. Если за время работы цикла выполнилось условие `b` - цикл досрочно завершится:
```lua
while a do
    if b then
        --"Горшочек не вари, б%#ть!"
        break
    end
end
```

Можно циклы складывать друг в друга, образуя ветки циклов:
```lua
while a do
    while b do
        
    end
end
```

#### Примеры использования:

Прибавляем к числу единицу, пока оно меньше максимума:
```lua
local a = 1
while 100 > a do
    a = a + 1
end
```
Досрочно выйдем из цикла:
```lua
local a = 1
while 100 > a do
    a = a + 1
    if a == 50 then
        break
    end
end
```
Прибавляем к числу единицу, пока оно меньше максимума:
```lua
local a = 1
while 100 > a do
    a = a + 1
end
```
Разложим случайные ящики с лутом по локациям `genericLocation` карты:
```lua
--Есть список пушек
local gunlist = {"hornet01","specter01","pkt01","kord01","storm01","rapier01","vector01","vulcan01","flag01","kpvt01","rainmetal01","bumblebee01","omega01"}
--Получим количество пушек из списка
local gun = getn(gunlist)
--Счетчик имен локаций
local n = 0
while getObj("loc_lootPlace"..n) do
    --Пока существует локация с именем loc_lootPlace<цифра>, будет выполнятся цикл (номера локации должны быть четко по порядку, в противном случае цикл закончится, так как выдаст nil и ящиков в других локах не будет)
    local rndLoot = gunlist[exrandom(gun)]
    --Получим случайную позицию пушки из списка (таргемовское казино)
    CreateBoxWithAffixGun(CVector(getPos("loc_lootPlace"..n)), rndLoot, random(3))
    --Здесь основное имя локации соединяется со значением счетчика, образуя полное имя объекта
    --Спавним ящик с оружием, полученном в rndLoot, в позиции локации loc_lootPlace<цифра>, с расхождением аффиксов со значением 3
    n = n + 1
    --Добавим +1 к счетчику имени локации
end
```

### Цикл repeat

Может стать особым счетчиком с проверкой условия.

- Впервые выполнит код в любом случае, а затем проверит условие.
- Выполняет код до тех пор, пока его условие не начнет выполняться.
- Существует только в моменте выполнения себя, где было объявлено.

> ***Если его условие всегда будет ложью или пустотой, он не завершится и игра зависнет!***

#### Синтаксис:

Простая проверка условия:
```lua
repeat

until a
```
| Кусочек кода | Определение |
|-----------|-----------|
| `repeat` | Начало тела цикла |
| от `repeat`<br>до `until` | Тело `repeat`.<br>Этот код внутри тела выполнится впервые в любом случае.|
| `a` | Условие - оно же конец `repeat`.<br>Является ли условие `a` ложью или пустым? Тогда код внутри тела будет выполняться. Иначе выход из цикла.|

> Код внутри цикла выполняется полностью, даже если условие изменилось на середине.

Работа цикла:
1. Выполнение кода внутри тела;
2. Проверка условия;
3. Если ложь или пустота - выполнение кода внутри тела;
4. Проверка условия;
5. Если ложь или пустота - выполнение кода внутри тела...

Выйти из цикла - `break`. Если за время работы цикла выполнилось условие `b` - цикл досрочно завершится:
```lua
repeat
    if b then
        --"Горшочек не вари, б%#ть!"
        break
    end
until a
```
Можно циклы складывать друг в друга, образуя ветки циклов:
```lua
repeat
    repeat

    until b
until a
```

#### Примеры использования:

Прибавляем к числу единицу, пока оно меньше максимума:
```lua
local a = 0
repeat
    a = a + 1
until a > 100 
```
Досрочно выйдем из цикла:
```lua
local a = 0
repeat
    a = a + 1
    if a == 50 then
        break
    end
until a > 100 
```
Этот цикл менее удобен, чем циклы `for` или `while`, но может быть полезен для *имитации* `goto`/`continue` (есть в Lua 5.1+):
```lua
for i = 1, 10 do
    repeat
        if math.mod(i, 2) == 0 then
            --Если число четное, переходим к следующей итерации (а эту прекращаем)
            break
            --Это действие имитирует continue
        end
        println(i)
        --Выводим нечетные числа
    until true
    --Здесь цикл repeat выполняется лишь один раз (не цикл по факту)
end
```

### Цикл for

Может стать продвинутым счетчиком или читателем таблиц.

- Выполняет код до тех пор, пока значение счетчика не станет равным его максимуму.
- Выполняет код до тех пор, пока индекс/ключ таблицы не станет `nil`.
- Принимает первую обязательную переменную как начальное значение счетчика или имя поля таблицы.
- Принимает вторую переменную как значение максимума счетчика или значение поля таблицы.
- Принимает третью необязательную переменную как значение шага счетчика.
- Существует только в моменте выполнения себя, где было объявлено.

> **Все переменные у for (такие как `i`) находятся локально внутри его тела и могут быть использованы его скриптом *(и названы как угодно)!***

#### Синтаксис:

<div align="center">
  <h4>Счетчики</h4>
</div>

Простой счетчик:
```lua
for i = 1, 10 do

end
```
| Кусочек кода | Определение |
|-----------|-----------|
| `for` | Начало проверки условия цикла |
| `i = 1` | Переменная `i` как начальное значение счетчика, равное `1`. |
| `,` | Разделитель переменных цикла |
| `10` | Значение максимума счетчика |
| `do` | Конец проверки условия цикла |
| от `do`<br>до `end` | Тело `for`.<br>Является ли счетчик `i` меньше максимума? Тогда код внутри тела будет выполняться, пока счетчик `i` не станет равным максимуму. Иначе выход из цикла.|
| `end` | Конец тела `for`. |

> Код внутри цикла выполняется полностью, даже если условие изменилось на середине.

Работа цикла:
1. Проверка счетчика (условия);
2. Если счетчик меньше максимума - выполнение кода внутри тела и добавление единицы к счетчику;
3. Проверка счетчика (условия);
4. Если счетчик меньше максимума - выполнение кода внутри тела и добавление единицы к счетчику...

Счетчик с настроенным шагом его изменения (третья переменная):
```lua
for i = 1, 10, -1 do

end
```
Если указан шаг, счетчик будет изменяться согласно ему. Если он отрицательный - будет вычитать, а не прибавлять.

Выйти из цикла - `break`. Если за время работы цикла выполнилось условие `a` - цикл досрочно завершится:
```lua
for i = 1, 10 do
    if a then
        --"Горшочек не вари, б%#ть!"
        break
    end
end
```
Можно циклы складывать друг в друга, образуя ветки циклов:
```lua
for i = 1, 10 do
    for j = 1, 5 do

    end
end
```

    LOG(i)

    --Получаем машину из команды PidoriTeam созданной в TeamCreate(). Здесь основное имя соединяется со значением счетчика, образуя полное имя объекта
    if vehicle then

  <h4>Читатели таблиц</h4>
</div>

> *По сути тоже счетчики...*

Простой перебор таблицы:
```lua
for i, v in ipairs(t) do

end
```
| Кусочек кода | Определение |
|-----------|-----------|
| `for` | Начало проверки условия цикла |
| `i` | Переменная `i`, принимающая индекс или ключ элемента таблицы. |
| `,` | Разделитель переменных цикла |
| `v` | Переменная `v`, принимающая значение индекса элемента таблицы. |
| `in` | Часть синтаксиса между переменными и функцией-итератором (разделитель). |
| `ipairs(t)` | Функция-итератор `ipairs` с помещенной в нее таблицей `t` (на ее месте может быть другая функция-итератор, например `pairs`). Она вычисляется один раз, а затем возвращает свои переменные кортежем при каждой итерации цикла, что принимают на себя `i` и `v` в нашем случае. <br><br> \* `ipairs` - читает таблицы-списки и возвращает только индексы и их значения; <br> \* `pairs` - читает таблицы-словари и возвращает ключи и индексы с их значениями *(медленнее, чем `ipairs`)*.|
| `do` | Конец проверки условия цикла |
| от `do`<br>до `end` | Тело `for`.<br>Является ли переменная `i` истиной? Тогда код внутри тела будет выполняться, пока `i` не станет ложью. Иначе выход из цикла.|
| `end` | Конец тела `for`. |

> Код внутри цикла выполняется полностью, даже если условие изменилось на середине.

Работа цикла:
1. Возврат индекса/ключа и его значения из таблицы в переменные;
2. Если первая переменная является истиной - выполнение кода внутри тела;
3. Возврат следующего индекса/ключа и его значения из таблицы в переменные;
4. Если первая переменная является истиной - выполнение кода внутри тела;
5. Возврат следующего индекса/ключа и его значения из таблицы в переменные...

Выйти из цикла - `break`. Если за время работы цикла выполнилось условие `a` - цикл досрочно завершится:
```lua
for i, v in ipairs(t) do
    if a then
        --"Горшочек не вари, б%#ть!"
        break
    end
end
```
Можно циклы складывать друг в друга, образуя ветки циклов:
```lua
for i1, v1 in ipairs(t1) do
    for i2, v2 in ipairs(t2) do

    end
end
```
